# n8n

**n8n** é uma ferramenta de **automação de fluxos** (*workflow automation*) orientada a nós: triggers (cron, webhook, Gmail, Slack…) + passos de lógica + chamadas HTTP + integrações prontas. Combina bem com IA quando precisas de **orquestrar** chamadas a APIs de modelo, normalizar dados e encadear sistemas **sem** escrever um backend completo.

---

## Quando faz sentido

- Integrar **ChatGPT/OpenAI-compatible**, **HTTP Request** para qualquer LLM cloud ou self-hosted.
- **Webhook** que recebe evento → enriquece contexto → chama modelo → grava CRM / envia email.
- Prototipagem rápida antes de mover lógica crítica para código versionado.

---

## Conceitos

| Conceito | Descrição |
|----------|-----------|
| **Workflow** | Grafo de nós com dados a fluir entre eles |
| **Trigger** | Início (tempo, HTTP, evento SaaS) |
| **Credential** | Segredos armazenados de forma segura (não em JSON de workflow) |
| **Expression** | `{{$json.field}}` para mapear saídas entre nós |

---

## Exemplo conceitual — webhook + LLM

1. **Webhook** — `POST /review` recebe `{ "ticket": "…" }`.
2. **Set** — normaliza campos.
3. **HTTP Request** — `POST` para endpoint OpenAI-compatible com prompt de classificação.
4. **IF** — se severidade alta → **Slack**; senão → **Google Sheets**.

---

## Self-host e devops

- **Docker** (`n8nio/n8n`) é comum; persiste volume para workflows e *encryption key*.
- **Variáveis de ambiente** para URLs e chaves — nunca embutir *API keys* exportando workflow.

---

## Limitações a conhecer

- Lógica complexa em muitos nós torna-se difícil de **testar** e **revêr** como código.
- **Rate limits** de APIs LLM — configurar *retry* e *backoff* nos nós HTTP.
